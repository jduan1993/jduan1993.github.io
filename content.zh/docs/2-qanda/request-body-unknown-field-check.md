---
title: 请求体包含未知属性导致 400 参数类型错误
---

## 1. 现象描述
- 客户端在调用更新状态等接口时，如果请求体 JSON 中传入了 DTO 中未定义的字段（例如在仅需要状态字段的请求体中多传入了主键 ID），接口返回 HTTP 400 状态码，并提示“参数类型错误”。

## 2. 原因分析
1. **反序列化配置覆盖**
   - 在标准 Spring Boot 默认配置下，反序列化遇到未知属性时通常会忽略（即 `FAIL_ON_UNKNOWN_PROPERTIES` 默认为关闭状态）。
   - 项目中自定义声明了 JSON 序列化映射器组件，直接使用了原生实例进行注册，导致覆盖了 Spring Boot 默认的宽松反序列化策略。
   - 原生实例默认开启了“遇到未知属性则抛出反序列化异常”的严格校验规则，因此请求体中只要存在 DTO 未声明的键，就会触发未知属性异常并终止请求体解析。

2. **全局异常兜底文案误导**
   - 请求体解析失败统一由全局异常处理器捕获（处理消息不可读异常）。
   - 当前异常处理逻辑中，主要对格式转换错误（如枚举类型不匹配）进行了针对性解析与文案定制；对于未知属性异常等其他原因导致的消息不可读，均走兜底逻辑，返回了默认文案“参数类型错误”。
   - 这导致实际是“字段未识别/未知字段”引发的解析中断，表现出来的提示却是“类型错误”。

## 3. 解决思路（供参考）
- **配置层兼容**：在自定义 JSON 映射器配置中，显式配置反序列化特性，关闭“遇到未知属性时报错”的限制，或者基于 Spring 提供的构建器保留默认配置。
- **DTO 粒度控制**：若仅希望特定 DTO 忽略未知属性，也可以在目标 DTO/Record 上使用忽略未知属性的注解。
- **异常捕获细化**：在全局异常处理中增加对未知属性异常的分支识别，给出更明确的错误信息（如“存在不支持的属性”），提升排查效率与接口友好度。
